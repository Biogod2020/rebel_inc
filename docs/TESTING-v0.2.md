### 第一环境的限制

该环境禁止 URL 导航，因此完整战役使用 `page.set_content` 载入已构建的单文件，只开启显式测试观察接口；自动保存使用显式内存适配器。存储拒绝分支另行测试。**这一部分本身不能证明 file:// 导航或跨浏览器会话持久性。** 为补足这点，又运行了下一节的独立原生检查。

## 如何复现

```bash
npm ci --ignore-scripts
npm run check
npm test
npm run balance
npm run build
```

完整界面测试需要额外的 Python Playwright 与 Chromium，不是游戏运行依赖：

```bash
python -m pip install playwright
CHROMIUM=/path/to/chromium python tests/browser_smoke.py
```

独立原生检查使用已安装的 Playwright Core：

```bash
PLAYWRIGHT_MODULE=/absolute/path/to/playwright-core \
CHROMIUM=/path/to/chrome node tests/native-browser.cjs
```

浏览器脚本将输出写入 `artifacts/`；该目录不提交到源码仓库。仓库 `docs/` 保存本次摘要，完整截图和操作记录单独交付。核心 CI 运行类型检查、规则测试与离线构建一致性检查，不假装在 CI 中执行了整局浏览器战役。

## 本轮修复与未验证项

本轮修复了调解执行阈值与界面说明不一致、火山委托在喷发后仍可能结算、延迟接受救援委托后错误延长期限、运输跨路段速度优势被整数截断等问题，并加入回归测试。界面重构包含详情切换滚动复位、背景焦点锁定与逐层展开。

没有做 Safari、Firefox、真实手机或用户 Mac 的实机检查；响应式窗口测试不能替代触屏测试。三场景共享地图生成框架，不是三个完全独立的关卡。仍需真人反馈才能判断是否足够美观、有趣，以及是否存在乏味的优势策略。本验收不宣称游戏达到统一的「SOTA」标准，也不将虚构规则当作真实社会或军事预测。
