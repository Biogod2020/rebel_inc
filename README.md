# 烬土 · AFTERFIRE

一个可以离线运行的原创实时重建策略游戏。你管理的不是一条升级进度条，而是一组互相牵制的系统：民生、施工、情报、补给、武装活动、财政、灾害与和平进程。

**当前版本：0.1.0。** 三个场景均有完整的开始、发展、事件决策、胜负和结算流程。地图、图标与音效均由代码生成，不使用 Rebel Inc. 的代码、商标美术、地图或音频；本项目与其开发商没有官方关系。这里的地名、冲突和数值都是虚构的游戏抽象。

## 直接玩

下载本仓库，打开根目录的 **`index.html`**。这个文件已经包含全部游戏代码与样式，不需要 npm、游戏引擎、API 密钥、登录或联网加载素材。

建议使用桌面 Chromium 系浏览器，窗口至少 1280 × 800。窄屏有响应式布局，但完整战役验收是在桌面尺寸进行的。文件预览服务通常不会执行游戏脚本，需要把 HTML 下载后用浏览器打开。

浏览器可能限制 `file://` 页面的本地存储。遇到保存限制时，从「行动手册」使用 **导出存档 / 导入存档**；也可以使用下方的本地服务器。新行动会覆盖自动存档，开始前请先导出需要保留的进度。

## 开发与运行

开发需要 **Node.js 22 或更高版本**。唯一的 npm 开发依赖是锁定版本的 TypeScript 5.8.3；游戏运行时没有第三方依赖。

```bash
npm ci --ignore-scripts
npm start
# 浏览器打开 http://127.0.0.1:4173
```

```bash
npm run check      # TypeScript 严格检查
npm test           # 25 项模型/回归测试，包含 27 局组合压力测试
npm run build      # 生成 dist/index.html，同时更新根目录 index.html
npm run balance    # 36 组脚本策略比较，输出 artifacts/balance-report.json
```

`npm start` 启动前构建一次；修改代码后重新构建并刷新即可。它不是带热更新的开发服务器。`HOST`、`PORT` 环境变量可以修改监听地址与端口，默认只监听本机。提交修改时运行构建，使已提交的离线 HTML 与源码一致；CI 会检查这个一致性。

## 一局怎么玩

首次建议选择「河谷重建 / 民政专员 / 宽松」。开局暂停，先点击人口中心，回应它的首要诉求，再招募部队。第 12 周武装出现，部队训练也需要时间。先保护城市与相连的道路，不必立即把所有兵力投入山地。

点击部队卡片或地图上的部队，再点击目的地区域即可下达行军命令。部队会沿邻接路线逐段移动；再次点击已选部队或右键取消选择。相邻驻军提供战斗支援，低补给削弱战力，突击姿态增加居民伤亡风险。工兵适合施工和疏散，不适合独自清剿。

地区的民心与稳定进度是两个不同的量。民心至少 53%、当地武装很少、补给连通，才能逐渐稳定。工程有工期，腐败、山地、冲突和断补给会拖慢进度。每 4 周发放预算并扣除部队维护费，不能把初始预算全部变成长期驻军。

「灰烬山脊」首次喷发在第 48 周，随后每隔 100 周再次喷发。关注金色危险区，点击后组织疏散；道路、工兵、安置设施和监测都会帮助转移。灾区关闭 12 周、损坏道路并把安置压力传给邻区。

有两条胜利路径，均需连续满足条件 8 周：

- 稳定至少 70% 人口、和平进程 100%，全区武装规模低于 65。
- 稳定至少 85% 人口，全区武装规模低于 5。

第 48 周后，民心至少 48%、武装规模低于 180、至少一级「调解与复员」，可在态势面板花费 $12 启动和谈。声望耗尽或第 360 周仍未达成目标则失败。人口比例按人口加权，不是地区数量比例。武装的真实规模受情报迷雾遮蔽。

## 操作

| 操作 | 控制 |
| --- | --- |
| 暂停 / 继续 | 空格或顶栏按钮 |
| 1× / 2× / 4× | `1` / `2` / `3` |
| 单步推进一周 | `.` 或 `。` 或顶栏单步按钮 |
| 地区 / 治理 / 部队 / 态势 | `B` / `P` / `U` / `I` |
| 保存 | `S` 或左下角保存按钮 |
| 手册及存档导入导出 | `H` / `?` 或问号按钮 |
| 缩放 / 平移 / 复位 | 滚轮 / 拖动 / `0` |

每 4 周自动保存；切到后台自动暂停。声音默认关闭，可以用左下角按钮开启。地图可切换地形、民心、补给、情报四个图层。

## 已实现的内容

35 个不规则地区，三个场景，三种治理者，三档难度，可输入种子复盘；8 类地方工程、6 类治理政策、3 类部队、3 种作战姿态；多阶段行军、补给连通、部队合同、施工队并行上限、通胀、腐败、人口诉求、相邻地区影响、武装撤退与渗透、周期性雨季、火山疏散、流离失所者安置、六类循环事件、和谈、两种胜利条件、自动保存、JSON 导入导出和结算曲线。

## 源码结构

```text
src/model.ts        类型、数据定义、可调参数、确定性随机数
src/world.ts        Voronoi 地区生成、邻接、Dijkstra 路线、补给图
src/simulation.ts   命令验证与逐周模拟、经济、战斗、工程、灾害、存档
src/render.ts       Canvas 2D 程序地形、动画、交互、图层与镜头
src/ui.ts           中文界面、决策窗口、控制器、存档与音效
src/main.ts         固定步长时钟与绘制循环
src/style.css       桌面与窄屏布局
scripts/            构建、服务器、测试与平衡比较入口
tests/              纯模型回归、测试策略、真实浏览器操作脚本
docs/               设计说明、验收范围和实际测试结果
index.html          已构建的完整离线游戏
```

TypeScript 的作用是让大量相互依赖的规则保有类型约束，并直接交付可玩的浏览器版本；不意味着它是所有游戏的「最佳语言」。这里不需要大型 3D 引擎。纯模拟与绘制分离，可以直接用 Node 测试游戏规则，之后也可以替换绘制层。

## 验收与边界

25 项自动测试全部通过；额外保存了 36 组策略比较结果。浏览器测试通过真实按钮、键盘和地图坐标完成一局标准难度火山战役，并验证导出、导入、暂停和响应式布局。具体环境、输入方式、限制和统计见 [docs/TESTING.md](docs/TESTING.md)。

这是完整可玩的首版，不是已经经过长期玩家测试的商业成品。敌方使用规则驱动策略，不是大模型；场景采用同一地区生成框架；音效是简短的程序合成提示音，不是完整配乐。没有多人、原生安装包、地图编辑器、真实世界冲突校准或 Safari / Firefox 实机验收。平衡脚本证明特定策略可通关，并不证明本作比商业游戏更有趣。
